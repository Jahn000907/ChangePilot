# ChangePilot 工程变更影响分析与执行智能体平台

**文档版本：v0.1**  
**文档状态：历史版本 / 已归档**  
**用途：记录项目最初的产品定位与总体技术方案，不作为当前实现基线。**

> 当前实现应优先参考 v0.3 业务/BOM 建模文档与 v0.4 数据库详细设计文档。

---

## 1. 项目定义

ChangePilot 是一个面向制造企业工程变更管理场景的多智能体系统。

系统接收来自供应商、工程、质量、客户或生产部门的工程变更事件，通过智能体协同完成：

1. 变更事件理解；
2. BOM 影响范围分析；
3. 下游业务事务影响分析；
4. 替代方案评估；
5. 工程变更方案生成；
6. 风险与完整性审查；
7. 人工审批；
8. 工程变更单和 BOM 修改草案创建；
9. 执行过程跟踪；
10. 全链路审计。

系统目标不是替代产品生命周期管理系统（PLM）或企业资源计划系统（ERP），而是在多个企业系统之上提供：

- 理解；
- 规划；
- 工具调用；
- 跨系统协调；
- 决策辅助；
- 受控执行。

## 2. MVP 核心业务场景

第一阶段聚焦：

**供应商零部件停产导致的工程变更。**

示例：

```text
Supplier: MotionWorks
Part Number: BRG-6204-A
事件：停止供应
最后采购日期：2026-11-30
正式停产日期：2027-01-31
推荐替代零件：BRG-6204-B
```

系统需要回答：

- 哪些 BOM 使用该零件；
- 哪些最终产品受到影响；
- 当前库存是多少；
- 是否存在未完成采购订单；
- 哪些生产订单受到影响；
- 哪些客户订单可能受到影响；
- 替代件是否合格；
- 应立即切换还是消耗旧库存后切换；
- 变更从何时生效；
- 是否需要人工审批。

## 3. 总体业务流程

```text
工程变更事件
↓
事件理解
↓
工程变更申请（ECR）
↓
影响分析
↓
替代方案评估
↓
变更方案生成
↓
风险审查
↓
人工审批
↓
工程变更单（ECO）
↓
BOM 修改草案
↓
执行
↓
验证
↓
关闭
```

## 4. 初始多智能体划分

### 4.1 事件理解与任务规划智能体

负责：

- 解析供应商通知；
- 提取零件、供应商、停产日期等结构化信息；
- 制定后续分析计划。

权限：只读。

### 4.2 影响分析智能体

负责：

- 多层 BOM 反向使用关系分析；
- 查询库存；
- 查询采购订单；
- 查询生产订单；
- 查询销售订单。

客观影响范围必须由图数据库和关系数据库计算，不由大模型猜测。

### 4.3 方案规划智能体

负责：

- 组织影响分析结果；
- 评估替代零件；
- 生成多个候选工程变更方案。

### 4.4 风险审查智能体

负责：

- 检查是否遗漏产品和订单；
- 检查替代件资格；
- 检查生效日期冲突；
- 检查旧库存处置；
- 判断是否必须人工升级。

### 4.5 变更执行智能体

唯一具有受控写权限的智能体。

必须在人工审批通过后才能：

- 创建 ECO 草案；
- 创建 BOM 修改草案；
- 设置生效条件；
- 标记受影响订单；
- 记录审计事件。

## 6. 核心设计原则

### 6.1 智能体不替代确定性系统

```text
自然语言理解 → 大模型
任务协调 → Agent
关系遍历 → Neo4j
业务查询 → SQL
计算 → Python
规则判断 → Rule Engine
高风险动作 → 人工审批
```

### 6.2 多智能体不能只是多提示词

不同智能体应具有不同的：

- 职责；
- 上下文；
- 工具；
- 权限。

### 6.3 写操作必须受控

正式修改企业主数据前必须：

```text
分析
↓
风险审查
↓
人工审批
↓
受控执行
↓
审计
```

## 7. 第一阶段不做

- CAD 修改；
- CAE 仿真；
- 真实 SAP / Teamcenter 集成；
- 完整 PLM；
- 完整 ERP；
- 复杂机械设计；
- 多工厂；
- 制造 BOM；
- 产品配置型 BOM。
